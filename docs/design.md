# CREW 设计共识

更新：2026-10-09。本文整理讨论中的当前决定，是设计说明，不代表现有代码已经实现。仅讨论手上的 CREW，不划分未来版本。概念图见 [concepts/index.html](concepts/index.html)。

## 目标

CREW 是可信团队与 AI 共用的终端工作空间。主要场景是人与 AI 开发项目、人与人操作服务器。用户应看得懂谁正在操作、操作在哪里、AI 做了什么，并能明确接管和归还。使用导航模式及操作占用防止误操作，不建立人员权限模型。

## 工作空间

- 一台服务器可运行多个 session；先 SSH 登录，再执行 `crew connect`。
- session 包含 tab，tab 包含 pane。window 仅表示布局与渲染，不承载权限。
- 参与者共享 tab、pane、内容、布局排列和比例，各连接独立选择 tab 和 pane。
- 多人布局操作由系统依次应用，不设布局独占；只支持 tab 内调整，跨 tab 移动留白。
- pane 必须有标题；交互创建时输入，命令可指定，缺省生成默认标题，随时可改。
- 无负责人、邀请授权、责任转移或上下级人员权限。任何人均能创建、调整、停止、关闭区域，启动或接管 AI；按操作影响提示确认。
- 关闭不能误杀任务成果服务；CREW 要提供进程脱离 session 的能力，使服务继续运行、CREW 可完全退出。具体关闭提示与进程交接流程留白，原“关闭前必须停止全部任务”规则不再定案。

## 导航与输入

| 模式 | 操作 |
| --- | --- |
| session 导航 | Vim 键位切换 tab；`i` 进入 tab；`a` 进入选中 tab 的 tab agent 对话 |
| tab 导航 | Vim 键位选择 pane；选中即观察；`i` 进入终端输入；`a` 进入 pane agent 对话；`q` 返回 session |
| 终端输入 | 按键发给终端；CREW 前缀键加 `q` 返回 tab 导航；前缀可转发给终端 |
| AI 对话输入 | Enter 发送，另一组合键换行；前缀键加 `q` 返回来源导航层 |

输入模式可用 CREW 前缀加 `a`／`i` 直接切换到对话／终端，保留人类操作位；切到对话不会自动恢复 AI，切到终端沿用 AI 接管规则。

私有回看在导航层使用专用键，输入模式使用前缀加同一键，具体键未定。tab 导航可进入独立布局编辑模式，移动或调整 pane，`q` 返回；布局编辑不独占。

`a` 在区域关闭时自动打开并进入对话输入，退出后保持打开。`Shift+A` 开关对应工具调用区与对话框。开关共享，不改变输入模式、不暂停 AI；正在被人操作的对话区不能关闭。没有 agent 时 `a` 只提示，不自动创建。tab agent 附属 pane 没有独立 agent，对话从 session 层访问。

## 占用与参与状态

- pane 同时只有一个人类操作连接；终端输入 `i` 与对话输入 `a` 共用这个位置。
- 人接替人：明确确认后直接接替，原操作者返回导航并收到提示；不自动停止已有进程。
- 同一个用户 ID 的不同连接同样需要接替。
- AI 可以在人对话时继续占用终端；人进入终端输入时暂停 AI。
- tab agent 对话同样只由一个人操作。
- tab 与 pane 的边框仅表达操作者，使用操作者主题色；无人操作时白色，即使有人观察。AI 与人同时操作时可分段着色。
- 观察者用区域右上角的用户名简称表示，使用各自主题色，例如 `xm · ln`；操作者不重复列入观察者名单。空间不足显示部分简称和 `+N`，完整名单按需查看。
- 人在终端或对话输入模式均算操作者，退出后成为观察者。AI 完成任务仍持有终端，保留其颜色并标明空闲或完成。
- session 层选中 tab 算 tab 观察者；pane 观察从进入 tab 并选中 pane 开始。
- 边框细节、AI 色彩分配及 tab 对话与附属终端的状态表达尚未确定。

## Agent 结构

CREW 内置 agent 循环；模型配置与 API 凭据由 session 共用。支持 OpenAI-compatible API，可自定义 base URL、模型和 API key；具体接口协议由开发时确定并记录。人明确选择 tab 或 pane 级 agent。

读取项目级 `AGENT.md`，另支持有一定自定义能力的 agent 说明文件。专家人格与 skill 系统明确列为 TODO，不作为当前必须实现的要求。任务结束后保留上下文继续协作，完成不是暂停，新消息直接触发工作；人工接管暂停需 `/resume`。新任务／清空操作新建一条对话，旧对话可切换查看，不删除记录。同一 agent 同时只有一条活动对话；旧对话可恢复继续协作，切换前需处理当前任务。tab agent 创建新对话前，运行中的子任务先暂停或结束，避免失去调度上下文。切换对话前结束当前命令，应保留的服务先脱离 session。新对话启动新的 Bash，保留文件与工作目录，不继承原 Bash 的临时状态；恢复旧对话同样启动新的 Bash，使用该对话的工作目录、保留当前文件，agent 重新检查环境；只恢复对话上下文，不恢复旧 shell 状态。文件位置、加载规则及操作名称待定。项目与自定义说明只能在 CREW 固定工具能力和运行规则内定制，不可突破这些规则。

- tab agent 有且只有一个独占的附属执行 pane，共用其上下文；可委派自带 pane 的工作 subagent。
- pane agent 没有委派工作 subagent 的工具，只能创建不拥有 pane 的只读探测助手。
- 探测助手仅有读取、列目录、搜索工具，无 shell、无测试、不能再委派。
- 系统先给新 pane 安排布局，人可调整。pane agent 完成后保留原 pane 和上下文，标记完成，等待后续任务。
- tab agent 工具区及对话框在页面右侧；pane agent 的在 pane 内右侧。开关状态共享；并排或覆盖终端显示由各客户端宽度决定，窄屏可采用覆盖。整体区域采用类似 agent CLI 的设计：对话与工具调用记录采用连续记录流，下方为输入框；脚本执行、文件修改等详细展示仍在主工作区，支持 `/` 命令。
- 对话输入草稿共享，接替者继续编辑；断线后保留，发送消息标记参与编辑的所有人。终端历史与 agent 对话／工具记录可进入各连接私有回看模式，滚动不影响别人、不新增公共操作占用、不暂停 AI。从输入模式进入时保留已有操作位，`q` 返回原输入模式；从导航进入时返回原导航层。回看期间被他人确认接替时，回看不中断，提示占用已移交，`q` 返回导航而非原输入模式。
- 对话共享，标明发送者；发送可选排队或立即打断。探测助手展示状态与结果，详情从所属 agent 工具区进入。
- 唯一附属 pane 不能在 tab agent 存在时关闭；结束 agent 后可关闭或转成人类 pane。tab 对话框与附属终端分别计算人类操作占用。

## 接管、暂停、恢复

- 对 AI pane 按 `i` 即明确接管。无运行命令时直接进入；有命令时选择是否中断。
- 接管 pane subagent 只暂停该 agent，并通知 tab agent；父 agent 可取消或重新分配任务，但不能收回人正在使用的 pane，应避免与人冲突。
- 接管 tab agent 的唯一附属终端时，只暂停 tab agent，已有 subagent 继续；与接管 pane agent 的行为一致。通过对话明确打断 tab agent 时，可选择只暂停它或暂停整个任务树。
- 离开输入模式、断线不自动恢复 AI。对话框 `/resume` 明确归还。
- 有人占用终端输入时，`/resume` 提示先结束占用；对话占用不阻止恢复。
- 恢复时自动交接工作目录内接管期间的文件变化与终端记录，AI 重新检查状态。文件变化可能包含其他人的同期修改，不应归因给接管者。
- 失败时 agent 可尝试恢复，无法继续则标记阻塞并通知人。

## 工具行为

- AI 固定使用 Bash。人按个人配置使用 shell。
- 人接管后 `crew load-config` 在 Bash 内启动个人 shell，退出回到 Bash；`/resume` 必须检查已回到原 AI Bash，否则提示人先退出个人 shell；人类 pane 交给 AI 时，在原 shell 内启动 Bash。
- 主工作区按当前工具自动展示脚本执行或文件修改，完成后保留结果；公共画面始终跟随当前工具，不允许固定视图，个人可私有回看；关闭右侧 agent 区域不隐藏这些展示。
- 命令可整体执行；展示完整脚本，高亮可定位的活动命令，并行允许多处标记；外部程序定位到调用行。无法定位时不伪造精确进度。
- 编辑工具先读取上下文，再精确替换或应用补丁；直接写入，展示上下文和差异。展示编辑器不接受人的直接编辑，人用自己的编辑器。
- 禁止 AI 主动通过 shell 编辑文件，以工具说明约束；Bash 本身仍可写入。
- 撤销只保证没有后续修改的文件；否则交给 Git 或人工。
- 共享工作目录，不锁文件、不强制隔离。工具说明要求委派安全可并行、互不依赖的任务。
- 工作目录是行为边界，访问外部目录需人确认，无系统隔离；子 agent 目录在父 agent 授权范围内。
- 这里的目录许可属于 agent 工作范围确认，不是人员权限模型；任何人都可处理请求。

## 终端显示与部署

- 对话、代码展示、工具记录按个人宽度排版。
- 实际终端保留统一屏幕坐标，小屏裁切或移动视口。pane 排列与比例共享，各客户端按自身尺寸布局。
- 终端尺寸跟随最近实际输入的人的显示尺寸，旁观不影响；AI 沿用最近尺寸。
- 在常见 Ubuntu 服务器上方便启动，尽量即插即用；可接受少量依赖库，避免大量额外组件和复杂环境准备。单文件、完全零依赖不作为硬要求；具体支持的平台、系统版本和依赖清单尚未确定。
- 参与者互信，可共用 SSH 账号，自行声明 CREW 用户 ID，不做身份认证；同一 ID 可有多个独立焦点的连接。
- 项目 `.crew` 保存配置、授权范围、布局和对话等记录；个人配置在 `.crew/users/`。不保存已撤掉的人员权限模型。
- 服务运行期间支持断线重连，任务继续；断线释放人的操作占用。服务退出后不恢复旧进程或运行中的任务。
- 底部状态栏展示状态与待处理请求，不抢焦点；快捷键进入处理；只有请求者等待，其他任务继续。F1 帮助。
- `crew` 命令提供交互流程，参数可跳过交互；快捷键作为辅助。创建 pane 默认加载创建者的个人终端配置。

## 尚待明确

1. tab agent 对话框与唯一附属终端分别占用时，操作者颜色如何在 tab 与 pane 上表达？
2. 私有回看与布局编辑的具体快捷键、复制／搜索方式；模式入口及输入目标切换规则已经明确。
3. agent 的主题色和多人边框细节；布局很窄时怎样保持可读？
4. AI 空闲 pane 的初始尺寸、尺寸变化时机，以及导航与复制/滚动的入口。
5. 常见 Ubuntu 的支持范围、可接受的依赖清单和安装方式。
6. `/resume` 要求人先退出个人 shell 回到原 AI Bash；具体如何可靠识别该状态待实现验证。
7. 支持进程脱离 session 后继续运行且 CREW 完全退出；进程输入输出、终端依赖与关闭交接流程待明确，不能误杀服务。
8. OpenAI-compatible API 的具体协议、模型上下文维护和重试边界由开发时确定并验证。
